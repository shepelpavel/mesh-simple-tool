# AGENTS.md

Правила работы в репозитории плагина. Читать до правок кода.

## Что это

Плагин редактора Godot на GDScript: кнопка `MST` в панели 3D-вьюпорта с операциями над UV/UV2
выбранного `MeshInstance3D`. Устройство решений — `docs/rfc/`, вход для человека — `README.md`.

## Структура

```
addons/mesh_simple_tool/
  plugin.cfg            манифест, версия плагина
  plugin.gd             EditorPlugin: вставка кнопки, меню, видимость по выделению
  uv_ops.gd             чистые операции над данными меша
  ui/scale_dialog.gd    окно масштабирования
  ui/unwrap_dialog.gd   окно развёртки
  ui/uv_preview.gd      отрисовка UV
  ui/merge_dialog.gd    окно слияния вершин
  tests/*.gd            headless-проверки
docs/rfc/               RFC по слоям + индекс
```

Каталог `addons/mesh_simple_tool/` — то, что копируется в проект-потребитель целиком. Ничего вне его
для работы плагина не нужно.

## Команды

Проверка синтаксиса (быстро, без редактора):

```sh
<godot> --headless --path <project> --check-only --script res://addons/mesh_simple_tool/plugin.gd
```

Тесты логики и сохранения:

```sh
<godot> --headless --path <project> --script res://addons/mesh_simple_tool/tests/uv_ops_check.gd
<godot> --headless --path <project> --script res://addons/mesh_simple_tool/tests/save_check.gd
<godot> --headless --path <project> --script res://addons/mesh_simple_tool/tests/merge_check.gd
```

Проверка порядка сигналов диалога:

```sh
<godot> --headless --path <project> --script res://addons/mesh_simple_tool/tests/dialog_signal_order.gd
```

Тесты логики и сохранения грузят сцену `res://tmp/test.tscn` (меш с UV1 и UV2) и ищут в ней ноду
`MeshInstance3D`; предполагается, что плагин уже лежит в `addons/` проекта.

Если в проекте есть автолоады, которые держат процесс (MCP-мост редактора и подобные), тест печатает
результат, но не выходит после `quit()` — тогда запускать с `timeout` и судить по `ALL CHECKS PASSED`
или гонять в чистом проекте-песочнице (2 с на прогон).

## Конвенции

- Скрипты `@tool`, потому что исполняются в редакторе. Логика, не зависящая от редактора, живёт
  в `uv_ops.gd` статическими функциями — её можно гонять headless без `EditorInterface`.
- `preload` внутри плагина — относительными путями (`../uv_ops.gd`), чтобы каталог можно было
  переименовать или переложить без правок кода.
- Файлы `.uid` коммитятся вместе со скриптами.
- Комментарии в коде не добавляются без явного запроса владельца.
- Временные файлы и бэкапы — вне репозитория, в scratch-каталоге агента.

## Границы

- Коммит и push — только по отдельной явной команде владельца. Одобрение работы, зелёные тесты
  и перезапуск редактора разрешением не считаются.
- Ничего не менять в проекте-потребителе, кроме `addons/mesh_simple_tool/` и строки подключения
  плагина в `project.godot`, и только когда владелец просит положить сборку для теста.
- Версия плагина живёт в `plugin.cfg`; при её подъёме других мест не искать.

## Грабли

- **`AcceptDialog` сначала скрывает окно, потом шлёт `confirmed`.** Обработчик `visibility_changed`
  срабатывает раньше подтверждения, и «Применить» превращается в отмену. Откат меша делать через
  `call_deferred`, а не напрямую в `visibility_changed` (RFC-0002).
- **Правка ресурса не делает сцену изменённой.** Мало применить данные к `ArrayMesh` — нужно
  `mesh.emit_changed()`, `EditorInterface.set_object_edited(mesh, true)` и
  `EditorInterface.mark_scene_as_unsaved()`, иначе Ctrl+S не сохранит правку (RFC-0002).
- **Официального API для расширения меню `Mesh` нет.** Кнопка ищется в дереве `base_control` среди
  `MenuButton` по наличию пункта с `UV2` в popup (работает и при переводе интерфейса), с откатом на
  текст `Mesh`. Живость кнопки проверяется каждые 0.4 с (панель пересоздаётся), полный обход дерева —
  раз в 2 с и по `selection_changed` (RFC-0001).
- **`lightmap_unwrap` меняет топологию.** xatlas может вернуть другое число вершин; восстановление
  исходного UV2 после развёртки возможно только при совпадении массивов вершин (RFC-0003).
- **`PrimitiveMesh` нельзя править на месте.** Примитив конвертируется в `ArrayMesh`, параметры
  примитива в инспекторе после этого недоступны (RFC-0002).
- **`Merge by distance` с нулевой дистанцией всё равно сливает вершины.** Порог обрезается до 1e-6,
  поэтому точно совпадающие позиции склеиваются при любом значении, включая 0. Это ожидаемое поведение
  (как в Blender), а не баг (RFC-0005).
- **`Merge by distance` считается по геометрии, UV не влияет.** Слияние идёт по позициям; UV, тангенты
  и цвета после него берутся у представителя группы. Галочка «Сохранять плоское затенение (учитывать
  нормали)» включена по умолчанию — тогда на тестовом меше сливаются 14 вершин; без неё — 66, но
  нормали усредняются и меш становится гладким. Причина: у остальных пар нормали расходятся под 90°
  (настоящие hard edges). В Godot нет split normals, поэтому «слить всё» и «сохранить вид»
  одновременно нельзя; в окне показаны оба числа (RFC-0005).
- **Пересборка поверхностей теряет blend shapes.** `ArrayMesh.clear_surfaces()` + `add_surface_from_arrays()`
  не переносит blend-данные, поэтому `check_supported()` блокирует такие меши, а диалоги отказываются
  открываться. Проверку не убирать (RFC-0002).
- **`_gather()` должен знать stride канала.** Атрибуты бывают с 1, 2, 4 и 8 значениями на вершину
  (custom 2D/3D, тангент, 4/8 весов скиннинга), а custom-атрибуты приходят как `PackedByteArray`
  с произвольным числом байт на вершину; при неизвестном размере `merged()` возвращает
  `ok = false` и меш не трогает (RFC-0005).
- **`--check-only` на файлах с автолоадами даёт ложную ошибку `Identifier not found`.** Для скриптов
  плагина неактуально — они не ссылаются на автолоады проекта.

## Куда писать знания

- Устройство и решения по подсистеме — в её RFC (`docs/rfc/`), новый слой — новый номер.
- Правила, команды и грабли, действующие для всего репозитория, — сюда.
- Открытые вопросы и планы — в RFC со статусом `draft`, а не в этот файл.
