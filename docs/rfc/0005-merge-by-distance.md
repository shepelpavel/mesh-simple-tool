# RFC-0005. Слияние вершин ближе заданной дистанции

- Статус: implemented
- Дата: 2026-11-23
- Влияет на: `addons/mesh_simple_tool/uv_ops.gd`, `addons/mesh_simple_tool/ui/merge_dialog.gd`,
  `addons/mesh_simple_tool/plugin.gd`

## Задача

Убирать из меша задвоенные и почти совпадающие вершины с настраиваемым порогом — аналог
`Merge by Distance` из Blender и `Merge by Dist` из meshbuilder.

## Решение

Пункт `Merge by distance` в меню `MST`. Окно с ползунком дистанции и полем ввода; под ползунком в
реальном времени показано, сколько вершин будет слито и сколько треугольников удалится. Слияние
применяется по кнопке «Применить»; «Отмена» ничего не меняет.

Алгоритм на поверхность:

1. Пространственная сетка с шагом `tol`: вершины раскладываются по ячейкам `floor(p / tol)`.
2. Union-find: для каждой вершины проверяются 27 соседних ячеек, пары ближе `tol` объединяются.
   При включённой галочке «Сохранять плоское затенение (учитывать нормали)» пара дополнительно
   проверяется: нормали должны совпадать (`dot >= 0.9999`). UV в сравнении не участвуют.
3. Представитель группы — вершина с наименьшим индексом: она задаёт позицию, UV, тангент, цвет и
   скиннинг-данные.
4. Индексы пересчитываются на группы; треугольники с двумя одинаковыми индексами отбрасываются
   (нулевая площадь).
5. Неиспользуемые вершины вычищаются, каналы атрибутов пересобираются по списку выживших.

Галочка включена по умолчанию: в тестовом меше сливаются 14 вершин. Без неё слияние идёт по позиции
(66 вершин из 94, остаётся 28 позиций), но нормали усредняются: у остальных пар они расходятся под
углами вплоть до 90°, то есть это настоящие hard edges, а не дубли. UV на слияние не влияет ни в
одном из режимов.

Счётчик показывает оба числа сразу: сколько сольётся в текущем режиме и сколько — в противоположном,
поэтому цена галочки видна до нажатия «Применить».

## Почему так

- **Нормали — единственное, что влияет на слияние сверх позиции; UV не влияет.** В Godot нет split
  normals: плоское затенение держится на раздельных вершинах с одинаковой позицией. Слияние по одной
  позиции склеивает их, нормали усредняются, меш становится гладким — поэтому есть опция учитывать
  нормали. UV в сравнении не участвует: слияние идёт по геометрии меша, как в Blender, где split normals
  и UV-острова живут отдельно от вершин. Побочный эффект: при включённой галочке «лишние» вершины
  остаются, а UV-шов после слияния берётся у представителя и может переехать.
- `Box`-развёртка выбирает ось по нормали вершины. На усреднённых нормалях (режим без галочки) она
  строит неверную проекцию — это не баг развёртки, а следствие потерянных hard edges; включайте
  галочку, если после merge планируете разворачивать UV.
- Пространственная сетка даёт линейный проход вместо квадратичного: в meshbuilder
  (`MBMeshData.build_welds_from_positions`) представители перебираются линейно по списку, что для
  крупных мешей квадратично. Здесь подход другой, идея операции — та же.
- Подсчёт статистики вынесен в отдельную функцию `merge_stats()`, которая делает только группировку
  и подсчёт вырожденных треугольников, без пересборки атрибутов. Окно вызывает её на каждое изменение
  ползунка (через `call_deferred`, не чаще раза в кадр), а тяжёлую пересборку делает только по
  «Применить».
- Диапазон ползунка привязан к диагонали меша (до 5 %), потому что абсолютный порог в метрах для
  мелких и крупных мешей означает разный результат.
- Вершина с меньшим индексом как представитель — детерминированный результат: повторный вызов с тем
  же порогом ничего не меняет.

## Реализация

`uv_ops.gd`:

- `merge_stats(snap, distance, keep_shading = true)` — `{merged, removed_tris}` без изменения данных.
- `merged(snap, distance, keep_shading = true)` — полный результат: `{ok, surfaces, merged, removed_tris}`.
- `_group_positions(verts, tol, normals, keep_shading)` — сетка + union-find с проверкой нормалей,
  возвращает `{of, roots, slot}`.
- `_degenerate_count(arrays, roots, slot)` — подсчёт треугольников, схлопнувшихся в точку.
- `_gather(src, roots, count)` — перенос атрибутивного канала по списку представителей (векторы,
  UV, цвета, скаляры и скиннинг с шагом 1/2/4/8, байтовые custom-атрибуты с произвольным шагом).
- `_find` / `_union` — union-find с привязкой большего корня к меньшему, поэтому корень всегда
  минимальный индекс группы.

`ui/merge_dialog.gd`:

- `open(mesh_instance)` — снапшот, число вершин, диапазон по `mesh.get_aabb()`: максимум 0.5 % диагонали
  (в пределах 0.0001…100), стартовое значение `max(diagonal * 0.001, max_distance * 0.001)`.
- `_refresh_info(force)` — троттлинг 100 мс через `call_deferred`/`SceneTreeTimer`; для мешей крупнее
  `BIG_MESH_VERTS = 30000` расчёт запускается только принудительно (отпускание ползунка, смена
  галочки, ввод в поле), иначе окно показывает подсказку — иначе полный проход по 27 ячейкам на
  каждое движение ползунка замораживает редактор.
- `_update_stats()` — `merge_stats()` с учётом галочки и текст «Будет слито N вершин, удалено M
  треугольников» плюс напоминание, учитываются ли нормали и UV.
- `_on_confirmed()` — `merged()` + `apply()`, `set_object_edited()` + `mark_scene_as_unsaved()`,
  тост с итогом через `EditorInterface.get_editor_toaster()`.

## Следствия

- `distance = 0` не означает «ничего не делать»: порог обрезается до `1e-6`, поэтому точно
  совпадающие вершины склеиваются. Так же ведёт себя Blender.
- При включённой галочке нормали не меняются вовсе: сливаются только вершины с одинаковыми нормалями,
  поэтому плоское затенение и hard edges сохраняются.
- Если галочку снять, нормали группы усредняются: меш становится гладким на месте слияния, а
  `Box`-развёртка начинает выбирать ось по усреднённой нормали и строит неверную проекцию.
- UV, тангенты и цвета берутся у представителя. При включённой галочке сливаются только вершины с
  одинаковым UV1, поэтому шов текстуры не переезжает.
- Слияние идёт внутри каждой поверхности отдельно; вершины разных поверхностей одного меша не
  объединяются.
- Треугольники нулевой площади удаляются, поэтому число поверхностей и вершин может уменьшиться.

## Вне текущего объёма

- Слияние между поверхностями и между разными мешами.
- Усреднение UV и цветов по группе.
- Живое применение к мешу при движении ползунка (в окне живой только счётчик).
- Запись в историю отмены редактора.
